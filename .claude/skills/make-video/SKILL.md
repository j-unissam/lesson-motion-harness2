# 수업 영상 만들기

`CLAUDE.md`의 규칙 3개를 지킨다: 내용은 교과서 md에서만, 룩 · 움직임은 docs와 references에서만(없으면 묻기), ✋에서 멈추기.
한 편의 모든 파일은 `out/<영상이름>/`에 둔다.

```
out/<영상이름>/
  brief.md      1 브리프
  content.md    2 교과서 정리      (content-editor)
  look.md       3 레퍼런스         (art-director)
  scenes.md     4 장면표           (director)
  snapboard/    5 스냅보드         (builder)
  review.md     5·6 검수           (critic)
  video/        6 HyperFrames 프로젝트 (builder)
  assets/       직접 그린 그림 + SOURCES.md (그림 출처)
  <영상이름>.mp4  7 렌더
  notes.md      8 규칙
```

## 1. 브리프 (직접)
아래를 **한 번에** 묻는다(AskUserQuestion). 기본값을 함께 보여 주고, 선생님이 고른 것만 `brief.md`에 적는다.
| 질문 | 기본값 | 근거 |
|---|---|---|
| 영상 이름 (폴더 이름, 영어 · 숫자 · 하이픈) | 예: `gas-3-1` | — |
| 다룰 소단원 | 3-1 ~ 3-6 중 선택 (여러 개 가능) | `docs/textbook/index.md` 영상 범위 |
| 목표 길이 | 2분 30초 안팎 | 레퍼런스 길이 2:24.5 |
| 소리 | 없음 (선생님이 수업에서 직접 설명) | 문서에 정한 값 없음 → 꼭 묻는다. 내레이션 · 음악을 고르면 그 파일을 어디서 가져올지도 묻는다 |
범위 밖 소단원을 원하면 멈추고, `index.md`의 범위를 바꿀지 묻는다.

## 2. 교과서 정리 (content-editor) → 영상에 쓸 부분 확인 ✋
- content-editor에게 `brief.md`를 주고 `content.md`를 받는다. 문장 · 그림 · 용어마다 "영상에 씀: 제안 O / X"가 붙어 있다.
- **영상에 쓸 부분을 선생님께 확인받는다.** 다음을 목록으로 보여 주고 하나하나 고르게 한다.
  - 화면에 쓸 문장 (번호 · 원문 앞부분 · 쪽 · 제안 O/X)
  - 보여 줄 실험 · 그림 (번호 · 무엇 · 쪽 · 제안 O/X)
  - 실험의 준비물 · 주의 · 안전 문구를 넣을지
  - 애매한 곳 질문
- 선생님이 고른 결과를 `content.md` 맨 아래 **"## 7. 영상에 쓸 부분 (선생님 확인)"**에 적는다: 확인한 날짜, 쓰는 것 번호 목록, 빼는 것 번호 목록.
- **✋ 멈춤.** 7장이 채워지기 전에는 3으로 가지 않는다. 고치라고 하면 content-editor에게 되돌린 뒤 다시 확인받는다.
- 이후 단계(장면표 · 생성)는 **7장에 "쓰는 것"으로 적힌 것만** 쓴다. 다른 문장이 필요해지면 그때 다시 확인받고 7장에 더한다.

## 3. 레퍼런스 (art-director)
- art-director에게 `content.md` · `brief.md`를 주고 `look.md`를 받는다.
- `look.md`의 "문서에 없는 값"이 비어 있지 않으면 선생님께 묻고 답을 적는다(잰 값과 출처 초를 함께 보여 준다). 다 정해지기 전에 4로 가지 않는다.
- 필요한 그림 목록을 선생님께 보여 준다. 직접 그릴지, 쓸 자료가 있는지 확인한다.

## 4. 장면표 ✋ (director)
- director에게 `content.md` · `look.md` · `brief.md`를 주고 `scenes.md`를 받는다.
- 선생님께 보여 줄 것: 전체 길이 · 장면 수 · 장면 제목 목록 · 마지막 정리 카드 3장 묶음 · 물을 것.
- **✋ 멈춤.** 승인 전에는 아무것도 만들지 않는다.

## 5. 스냅보드 ✋ (builder → critic)
- builder가 장면마다 "다 나온 순간" 한 장을 `snapboard/`에 찍는다.
- critic이 스냅보드를 검수해 `review.md`(스냅보드 단계)를 쓴다. "막음"이 있으면 builder가 고치고 다시 찍는다.
- 선생님께 스냅보드 전체를 보여 준다(파일로 보내기). critic이 "물을 것"으로 올린 것도 같이 묻는다.
- **✋ 멈춤.** 승인 전에는 움직임을 붙이지 않는다.

## 6. 생성 · 검수 (builder ↔ critic)
- builder가 장면표 시간대로 전체 영상을 만들고 `check` · `snapshot --review`까지 한다.
- critic이 완성본을 검수한다(`review.md` 완성 n차). "막음"과 "고침"은 builder가 고친다.
- 고침과 검수를 **최대 3번** 오간다(스냅보드 단계도 같다). 그래도 남은 지적은 선생님께 묻는다.
- 다 되면 HyperFrames 미리보기를 연다(`npx hyperframes preview`). 선생님께 미리보기에서 직접 글을 고칠 수 있다고 알린다.

## 7. 렌더
- 선생님이 미리보기를 승인하면 builder가 렌더한다 → `out/<영상이름>/<영상이름>.mp4`.
- 렌더 뒤 길이 · 크기(1920×1080) · 30fps를 `ffprobe`로 확인하고 파일을 보낸다.

## 8. 규칙
- 이번 영상에서 새로 정한 값(선생님 답, 레퍼런스에서 새로 잰 값)을 `notes.md`에 모은다. 그리고 선생님께 묻는다: "다음 영상에서도 쓰게 `docs/design.md` · `motion.md` · `video.md`에 넣을까요?"
- 승인받은 것만 문서에 넣는다. 문서를 고치면 `src/parts/` · `tokens.css`도 같이 맞춘다.
- `out/` · 교과서 변환본은 커밋하지 않는다.

## 언제든 멈추고 물을 때
- 문서와 레퍼런스 어디에도 없는 값이 필요할 때
- 교과서 원문을 줄이거나 바꿔야만 화면에 들어갈 때
- 범위(3-1 ~ 3-6) 밖 내용이 필요해 보일 때
- critic의 "막음"이 3번 오가도 풀리지 않을 때
